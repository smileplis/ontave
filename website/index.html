No second model call to draw a control. Your agent supplies a bounded question; Ontave validates the structure and renders the choices.

  1. 01

    Your agent asks.

    A typed specification defines the question, labels, controls, and options. Your application saves it with the conversation.

  2. 02

    Your user answers.

    Familiar controls collect the response. Selection stays local until the person presses Continue.

  3. 03

    The conversation continues.

    Validate against the saved question, normalize the values, and pass useful context to the same agent.

A few things, made clear

A little context
before you build.

What does Ontave do?

Ontave gives AI agents a bounded way to ask interactive questions. It provides TypeScript contracts, response validation, portable saved replies, provider adapters, and an optional React renderer. Your application continues to own the conversation and its data.

Does Ontave make another model call?

Rendering a question and selecting an option make no model request. Pressing Continue invokes your application’s callback. Any subsequent model call follows your existing conversation executor and budget.

Can a choice approve or execute an action?

A response provides conversational context. Your application must keep its existing permissions and approval flow for consequential actions. A “Yes” answer does not authorize a booking, payment, publication, or record change.

Do I have to use React?

No. The core and provider adapters work without React. Native clients can use the same contracts and register their own trusted control adapters. React is an optional peer dependency.

What happened to the earlier data framework?

The Ontave name now belongs to this interactive conversation framework. The earlier ontology framework is a legacy archive, with its historical releases and license preserved. It is a different API; the migration guide explains the change. No data is automatically migrated.

What has been verified?

The framework has deterministic coverage for validation, provider-call fixtures, keyboard interaction, retries, and saved readback. The playground uses local fictional examples. It does not demonstrate live model accuracy or paid-provider acceptance.
