A framework made of replaceable parts

Your model. Your data.
Your way forward.

Use an interaction inside an existing application, or compose a new application from a definition. Models, views, storage, workflows, and source exporters have separate interfaces.

  1. 01

    Connect your model.

    The host supplies its own SDK and budget. Ontave advertises installed capabilities and validates the returned definition before it runs.

  2. 02

    Install your capabilities.

    Start with collection views, dashboards, field updates, and queued events. Register trusted views and workflow modules as your application grows.

  3. 03

    Choose your foundation.

    Run through the shared runtime or export source. Keep authentication, production storage, integrations, and deployment under your host’s control.

A few things, made clear

Room to grow.
A concrete place to start.

What can I build today?

The experimental application layer supports bounded entity-based applications with linked records, CRUD forms and tables, count dashboards, and transactional workflows. The CRM demonstrates a complete local vertical slice. Arbitrary production application generation, cloud provisioning, migrations, and production database adapters are future work.

Does it produce a definition or code?

Both. Run the validated definition through registered views, or export editable React pages with a local Node API and persistent file storage. User-owned extension files survive regeneration; edited generated files cause a conflict for you to review. Code edits are not automatically converted back into definitions.

Can I use any LLM?

The model interface is a provider-neutral host callback. Your integration supplies structured JSON or a JSON string; Ontave validates it against the contract and installed capabilities. The framework bundles no model client and performs no hidden retries. The current demo uses fixtures, so it does not establish live model reliability.

Is interactive chat still available?

Yes. Questions, controls, validated replies, provider adapters and the optional React form remain independent exports. Use them in an existing application without adopting the application runtime.

Can a model install code or execute integrations?

A model can describe only installed capabilities. The host registers executable modules, controls permissions, and dispatches queued external effects. The reference app does not send emails, update an external CRM, or deploy itself.

What happened to the earlier Ontave?

The Ontave name now belongs to this modular framework. The previous ontology framework remains a legacy archive with its historical releases and license. It has a different API and no automatic data migration. See the migration guide.
